# 写操作约定

`booth-cloud` / `booth-agent` / `booth-web` 对外说法保持一致。

用户在客服里说退货、取消待付款、改地址等：

1. Agent 校验（身份、订单归属、状态等）
2. 通过后直接调商城网关提交，**不弹确认卡**（也不走已废弃的 `POST /app/chat/confirm`）
3. 受写熔断约束；用参数指纹 + outbox 做幂等，避免连点建脏单

Web 客服主路径：`POST /app/chat/stream`（SSE）。同步 `/app/chat` 只做降级。

不要写「确认卡防误触」，除非以后又改回确认流。
